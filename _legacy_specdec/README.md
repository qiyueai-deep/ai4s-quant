# 理论指导的投机解码:自训练、自基准、运行时自适应 draft 长度

本项目在自己的仓库里从头训练 target 与 draft 两个语言模型,自建 KV cache 解码基准,并在其上验证投机解码的四条命题。不依赖外部模型仓库、不用 transformers、不联网:README 里所有数字都由本仓库代码在单机 CPU 上产出,三条命令可复现。

对应岗位关键词:LLM 推理优化、speculative decoding、知识蒸馏、KV cache、接受率、延迟与吞吐权衡、PyTorch。

## 四条命题与实测结果

| | 命题 | 在自训练模型对上的结果 |
|---|---|---|
| A | 接受率恒等式 `alpha = sum_x min(p,q) = 1 - TV(p,q)`,Pinsker 下界 `alpha >= 1 - sqrt(KL/2)` | 1536 个真实分布对:恒等式误差 3.3e-16,Monte-Carlo 校验 3.7e-3,Pinsker 下界 1536/1536 成立;alpha = 0.9401(8 个前缀种子 0.922-0.958) |
| B | `S(K) = E[N_K]/(c0 + gK)` 存在有限内点最优 | 成本拟合 c0 = 1.70,g = 0.223,R² = 0.988;预测 K\* = 4,实测 K\* = 4,偏差 0;排序相关 0.988 |
| C | KL 预算经 Pinsker 给出接受率下界;蒸馏买到这个下界 | KL(T=2):同预算 SFT draft 0.387 → 蒸馏 0.109;下界 0.560 → 0.766;贪婪一致率 0.844 → 0.865;两个 draft 的实测一致率均不低于各自下界 |
| D | 最优 K 可以在运行时在线选择,不需要离线扫参 | 自适应控制器 1.265×,oracle 固定 K = 4 为 1.279×(达到 oracle 的 98.8%);固定 K = 16 掉到 0.759× |

## 系统

- 语料:确定性配置日志语言(`specdec/data.py`),9,000 行,短词模板加 episode 级上下文依赖。**禁止连续重复行**:在含重复行的语料上训练的模型学会"行级重复合法",贪婪路径塌缩成 `set 6/set 6/...` 循环,退化区接受率实测掉到 0.07。这是踩过并修掉的坑,不是拍脑袋。
- Target:d = 256,6 层,8 头,d_ff = 1024,4,790,528 参数,val CE 0.595,CPU 上 800 步 Adam 约 11 分钟。
- Draft:d = 64,2 层,113,984 参数(42× 压缩),T = 2 软目标 + 0.3 硬交叉熵蒸馏 900 步。
- 解码引擎(`specdec/decode.py`):KV cache 带回滚,标准轮结构的贪婪投机解码,每轮仅一次 target 前向(上一轮 bonus token 的 KV 作为下一轮验证输入的首位计算,永不单独前向)。正确性契约:**投机输出与 target 贪婪输出逐 token 完全一致**,对所有 K 与两个控制器成立,由单测强制。

## 基准(`python -m specdec.benchmark`)

24 条验证集 prompt × 64 token。共享 CPU 墙钟漂移大,因此每轮重复里基线与全部配置背靠背运行,speedup 逐对计算取 5 次配对重复的中位数(括号内为最小/最大)。

| K | 墙钟加速 | 接受率 | 每 token 的 target 前向数 |
|---|---|---|---|
| 2 | 1.156 [1.071, 1.207] | 0.705 | 0.418 |
| 4 | 1.279 [1.036, 1.414] | 0.560 | 0.312 |
| 6 | 1.193 [1.119, 1.352] | 0.443 | 0.277 |
| 8 | 1.200 [0.903, 1.287] | 0.370 | 0.256 |
| 12 | 0.981 [0.915, 1.056] | 0.268 | 0.241 |
| 16 | 0.759 [0.690, 0.852] | 0.215 | 0.228 |
| 32 | 0.510 [0.289, 0.686] | 0.110 | 0.225 |

曲线形状与命题 B 的预测一致:平坦最优区在 K = 4-8,K 大时跌破 1.0——接受率随上下文深度衰减(轮内第一个 slot 0.89,越深越低),而每轮成本线性增长。

## 自适应控制器(命题 D,本项目的方法贡献)

`AdaptiveController` 不做任何离线扫参:

1. 构造时直接在真实机器上计时两个原语成本:(K+1) token 的验证前向与单个 draft 步;
2. 解码中维护指数衰减、Laplace 平滑的接受率估计,只统计**实际测过的 slot**(每轮贡献 `match` 个成功,若以 mismatch 结束再计恰好一个失败;把从未到达的 slot 记作失败会把估计拉偏——实测被拉到 0.53,真实值 0.70,这是一个真 bug 修掉的过程);
3. `entropy_bucketing` 按 draft 熵分桶维护各自估计,因为 target-draft 差距依赖上下文(draft 分布平坦时与 target 更一致);
4. 按命题 B 的成本模型选 `K = argmax_K (1 - a^(K+1))/(1-a) / (c_block(K+1) + g(K+1))`,其中 a 在线估计。

结果:adaptive-global 1.265×,为离线扫参找到的 oracle 固定 K 的 98.8%;分桶版 K 在 [1, 7] 自适应,均值 4.0,两桶接受率估计 0.794(draft 低熵)与 0.569(高熵)。而随手选固定 K = 16 的运行速度只有 0.759×。

## 命题 C 有一处如实的反转

朴素预期是蒸馏全面占优。实测不是:蒸馏 draft 的 KL 更低(0.109 vs SFT 的 0.387),但 Pinsker 下界(0.766 vs 0.560)与贪婪 argmax 一致率(0.865 vs 0.844)的改善远小于 KL 的改善。分布匹配与 argmax 对齐是两个不同目标,而贪婪投机解码只消耗后者;蒸馏损失里 0.3 的硬 CE 权重就是两者之间的旋钮。两个 draft 的实测一致率都验证了不低于各自 KL 给出的下界。

## 复现

```bash
pip install -r requirements.txt
python tests_llm.py -v                 # 21 条断言
python -m specdec.train --force        # 约 11 CPU 分钟,确定性
python -m specdec.benchmark            # 约 8 CPU 分钟
python experiments_llm.py              # 命题 A-D,图表,summary
python experiments_llm.py --seed 7 --out results_llm_seed7   # 复现
```

仓库已自带 `artifacts/`(训练产物与 benchmark.json),直接跑实验即可;训练确定性(语料、初始化、批采样、评估上下文全部固定种子),基准的解码输出确定性,只有墙钟是测量值。

## 如实写明的边界

- 加速存在的前提是 target 单步 2.9 ms 而 draft 单步 0.48 ms(比值 0.17)。target 更小时同一套代码实测过 1.0× 以下:每前向的调度开销主导,没有可摊销的余量。仓库里保留了前向时间随参数量的实测标度表,标出分界在哪。
- 模型是 33 词表上的字符级模型,语料是合成的。理论可迁移,绝对数字不能直接对应生产级 LLM。
- 命题 A 是随机模式恒等式(采样前缀),基准是贪婪模式,两者分别报告,不作等同。
- 5 次配对重复的中位数仍带约 ±10% 的机器噪声;每个配置的最小/最大区间都在 `artifacts/benchmark.json`。
